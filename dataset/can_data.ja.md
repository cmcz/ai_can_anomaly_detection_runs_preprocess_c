# CANバスデータセット

本プロジェクトで使う生CANデータの説明。ここには「データが何か・どう並んで
いるか・プロファイリングで分かったこと」を記録する。

英語版: [`can_data.md`](can_data.md)

## 出所

- **車両**: Renault Euro VI 大型トラック(単一車両)。
- **収集**: 実路走行(ダイナモではない)。
- **規格**: SAE J1939 / FMS、250 kbit/s、全データフレーム、拡張(29ビット)ID。
- **内容**: 正常トラフィックのみ。記録内に攻撃・異常は含まれない。
- **原典**: トゥルク大学(University of Turku)J1939 トラックデータセット。
  https://etsin.fairdata.fi/dataset/7586f24f-c91b-41df-92af-283524de8b3e/data
- **ライセンス**: CC BY 4.0、オープンアクセス。

## 入手方法

上の Etsin のページから `part_1.tar.xz` から `part_4.tar.xz` を `data/` にダウンロードする。
合計で約 3 GB。各アーカイブは展開するとそれぞれ `part_N/` になるので、名前を変える必要は
ない。

```
cd data
tar -xJf part_1.tar.xz
tar -xJf part_2.tar.xz
tar -xJf part_3.tar.xz
tar -xJf part_4.tar.xz
```

## ディスク上の構成

```
data/
  part_1/   CSVログ 約2,800
  part_2/   CSVログ 約2,800
  part_3/   CSVログ 約2,800
  part_4/   CSVログ 約2,800
```

- CSVログは合計 **約11,194**。
- 各ログはきっかり **50,001行**(標本1,200ログ中1,200ログ)。
- 総フレーム数は **約5.6億** のオーダー。

各ログは独立したキャプチャだが、**時間的に連続しているとは限らない**。記録が
途中で停止して再開することがあり、通常のログの中に長い空白が1つ空く。

| 1ログの時間幅 | 割合 |
|------------------|------|
| 約59秒(p1〜p90 が 58.6〜59.4秒) | 約98% |
| 2分超  | 2.2% |
| 10分超 | 1.6% |
| 1時間超 | 0.8% |

つまり典型的なログは **約1分** の記録で、毎秒約850フレーム。標本中の最長は
**70.8時間** で、50,001フレームが1つの70.6時間の空白の前後に分かれている。

## CSVフォーマット

セミコロン区切り、1行=1 CANフレーム、先頭にヘッダ行。

```
timestamp;id;dlc;data
2020-11-23 08:03:31.985194;0x10ff80e6;8;0;0;251;109;240;144;255;255
2020-11-23 08:03:31.988986;0x1cff80e6;1;230
```

| 列          | 意味                                                            |
|-------------|-----------------------------------------------------------------|
| `timestamp` | `YYYY-MM-DD HH:MM:SS.ffffff`、マイクロ秒精度                     |
| `id`        | 29ビット拡張アービトレーションID、16進(例 `0x18f004e6`)         |
| `dlc`       | データ長(バイト)。大半は8、1・3・4も観測                      |
| `data`      | `dlc` 個の **10進** バイト値(0〜255)を各列に                   |

先頭3列(`timestamp`・`id`・`dlc`)は固定で、その後ろに `dlc` 個のデータバイトが
並ぶ。つまり1行の総列数は「3 + dlc」になる。

- 例: `dlc=8` は 3 + 8 = **11列**(データバイトは4〜11列目)
- 例: `dlc=1` は 3 + 1 = **4列**(データバイトは4列目の1個だけ)

データバイトは4列目以降に並び、値は **16進ではなく10進**。

## 識別子と信号

29ビットIDが PGN(メッセージ種別)とソースアドレスにどう分解されるかは、コードの
隣の [preprocess/docs/can_id_decompose.md](../preprocess/docs/can_id_decompose.md)
に記載。PGNは1つ以上の SPN(車速やエンジン回転などの個別信号)を運び、固定の
スケールとオフセットでペイロードから物理値に変換される。

フィールド定義の入手先は2つある。
[FMS-Standard description](https://www.fms-standard.com/Truck/down_load/fms%20document_v_05_vers.07.07.2024.pdf)
は無償で、このデータを記録したインターフェースそのものを定義しており、対象パラメータ
ごとにバイト位置、ビット位置、分解能、オフセット、送信周期を与える。44PGNを定義し、
うち18種がこのバス上にあり、フレームの28.6%を占める。それ以外は有償の
SAE J1939-71 が必要。

ログをプロファイルして分かったことは [measurements](measurements.ja.md) にある。
