# ルールの測定

[instant](instant) と [rate](rate) のルールが依拠する測定と、測って採用しなかった
候補の記録。データセット自体の測定は
[dataset/measurements.ja.md](../dataset/measurements.ja.md) にある。

英語版: [`measurements.md`](measurements.md)

## ルールが依拠するもの

### ルールが発火する頻度

[rules](README.md) の全ルールを584,694回、デコード1フレームにつき1回評価した
結果。割合の分母は全評価なので、各ルールのドキュメントが載せる値より小さい。あちらは
そのルールが適用される評価だけを分母にしている。

| ルール | 発火 | 割合 |
|---|---|---|
| range_check | 0 | 0% |
| speed_agreement | 39 | 0.0067% |
| shaft_ratio | 26 | 0.0044% |
| gear_ratio | 12 | 0.0021% |
| steering_sign | 68 | 0.0116% |
| engine_off | 0 | 0% |
| pedal_conflict | 0 | 0% |
| stopped_shaft | 0 | 0% |
| reverse_speed | 0 | 0% |
| いずれか | 145 | 0.0248% |

2本以上が同時に発火する評価は無い。

8本のうち4本は、同じ量の2つの読みか、2つの間の固定比を見ている。残り4本は他に何が
成り立つかを問うて得たもので、走行中以外にもルールが届くようになったのはこの4本に
よる。

| ルール | 問うていること | 正常データで外れる頻度 |
|---|---|---|
| steering_sign | 操舵角とヨーレートが同じ向きか | 0.02 rad/s 超の35,715件中6件 |
| engine_off | エンジンが0のとき、駆動される6信号も0か | 97,237件中0件 |
| pedal_conflict | 両ペダルが同時に踏まれていないか | 486,544件中0件 |
| stopped_shaft | 車輪が0のとき出力軸も0か | 最大31 rpm、閾値は50 |

VDC2 を見るのは steering_sign だけである。あの信号は大きさでは検査できないが、
向きなら検査できる。

[change_limit](rate/docs/change_limit.md) は表に入っていない。状態全体では
なく信号を自身の前の値と比べるので、評価の単位が違う。70ログ・949,349比較で2件発火。

### 定義域を外れる値は無い

デコードした値はすべて、`spn_spec` が記録する J1939 の定義域と照合している。100
ログ分で17信号・5,034,836値になるが、外れるものは1つもない。ルール層のレンジ
チェックは、このデータでは誤検知ゼロから始められる。

### 各信号が動ける速さ

同じメッセージの1フレームから次のフレームまでで測定。25ログ分。

| 信号 | 秒あたり最大 | 信号 | 秒あたり最大 |
|---|---|---|---|
| yaw_rate | 1.1 rad/s2 | fuel_rate | 94.5 L/h |
| steering_angle | 16.4 rad/s | actual_engine_torque | 747.3ポイント |
| wheel_speed | 21.0 km/h | output_shaft_speed | 3,010 rpm |
| tachograph_speed | 41.9 km/h | engine_speed | 3,277 rpm |
| current_gear | 80段 | clutch_slip | 3,790ポイント |
| selected_gear | 120段 | input_shaft_speed | 75,235 rpm |

左列上3行の4信号はトラックの能力で上限が決まり、
[change_limit](rate/docs/change_limit.md) が見ている。残りは決まらない。
変速で入力軸が解放され、クラッチスリップもそれに従い、ギア番号は数段飛ぶ。

100msグリッド上で標本を取ると、速い信号の値は小さく出る。エンジン回転はここでは
毎秒3,277 rpm だが、グリッド上では1,951 rpm になる。グリッドの1行は100msの間に
届いたものをまとめるので、5回分の更新が1つの差に畳まれるためである。一方で測った
上限をもう一方に流用することはできない。

## ルールにならなかったもの

### 一致するはずだった信号の組

以下の4組はどれも、同じ量を2通りに読んだものである。だから一致するはずで、ルールは
その一致を検査できる。成立するかどうかは、正常データで2つがどれだけ離れるかを、その量
自体が動く範囲と比べて決まる。

| 組 | ずれ p99 | その量が動く範囲 | 比 |
|---|---|---|---|
| wheel_speed と tachograph_speed | 0.90 km/h | 90.10 | 1.0% |
| engine_load と actual_engine_torque | 10.0ポイント | 52.00 | 19.2% |
| lateral_accel と 車速×yaw_rate | 0.69 m/s2 | 1.51 | 45.7% |
| accel_pedal と driver_demand_torque | 70.0ポイント | 92.80 | 75.4% |

最初の組は90 km/h の範囲に対して0.90 km/h しか離れないので、そのすぐ上に閾値を置けば
ほとんどの改竄を捕まえられる。これが [speed_agreement](instant/docs/speed_agreement.md)
である。最後の組は93のうち70離れるので、閾値で捕まえられる余地がほとんど残らない。
これにも、中間の2組にもルールを書いていない。

組を相関で選別してはいけない。最後の組の相関は0.803ある。

### 成り立たなかった他の主張

他に5つの形を試した。いずれも正常データが破らないはずの主張である。

| 主張 | 正常データが破る頻度 |
|---|---|
| 後退中は低速のまま | 87,245件で3.5 km/h を超えず |
| 稼働中のエンジンは燃料を使う | 6.4%。惰行時の燃料カット |
| 実トルクは要求トルクを超えない | 48.6% |
| 実トルクはエンジン負荷を超えない | 1.4% |
| 選択ギアと現在ギアは1段差に収まる | 最大12段 |

成り立つのは最初のものだけで、
[reverse_speed](instant/docs/reverse_speed.md) がそれである。他をルールに
すれば、右列の頻度でそのまま誤検知になる。

### 入力軸を検査しない理由

未実装のルール候補。クラッチが閉じていれば両者は一緒に回るはずで、p90 では 2.9 rpm
以内に収まる。しかし2.26%の行では最大618 rpm 食い違い、しかも低速・低段で持続する。
一例はエンジン1552に対し入力軸934、報告されるスリップは0。

ETC1 のバイト1が駆動系とトルクコンバータの状態を持ち、理由を説明できるはずだが、この
データでは204、205、221の3値しか取らずビットを確定できない。確定するまで、2.26%は
既存のルールより2桁悪い。

### 書いていないメッセージ側の検査

あと4つ検査が作れる。メッセージの種類ごとに周期が固定で、送信元が固定で、バイト数が
固定で、そもそも57種類しか現れない。いずれも上で測定済みである。

これらが捕まえるのは別種の攻撃で、フレームを追加する、落とす、偽造する類のものである。
そうした攻撃をまだ合成していないため、突き合わせる対象が無く、どれも書いていない。
